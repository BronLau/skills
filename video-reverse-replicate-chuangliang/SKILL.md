# 视频逆向复刻 · 创量版（抽帧 I2I 参考图 + 无字幕）

把一段成片视频逆向拆解为「可复刻的生产素材包」：分镜大纲 + 角色/场景参考图 + 每段可直接复制的生视频 Prompt。与底座 `video-reverse-replicate` 的三点差异：

1. **角色参考图走抽帧 I2I**：不再纯文生图"重画"角色，而是从原片按角色抽帧，用「原片帧（锁身份）+ 角色卡 Prompt（锁构图/姿态/背景）」图生图，保证参考图与原片真人严格一致——创量复刻素材对人物还原度要求极高，文生图再准也会"长得像但不是"。
2. **全程无字幕**：即使原片带字幕压屏，复刻成片不叠加任何字幕。第二步时间轴、第三步 ★Prompt 均不写字幕字段，台词只作为音频对白；★Prompt 首行统一声明"画面全程无字幕、无任何叠加文字"。
3. **生成段上限 30 秒**：创量链路的视频模型支持单次直接生成 30 秒，段时长上限由底座的 ≤15s 放宽到 ≤30s——剧情连贯的连续镜头尽量打包满（接近 30s），段越少跨段衔接点越少；但不为凑时长把场景/时空跨度大的镜头硬塞同一段。

其余流程（三步分工、音频事实保护、检查点）与底座完全一致；生成段方案沿用底座逻辑，仅段时长上限不同。

## 流程总览

```
任务进度：
- [ ] 0. 前置检查（API Key、依赖、视频大小）
- [ ] 1. 第一步分析（qwen3.8-max 看片）：选角与置景 → 分镜大纲.md（分镜+角色卡+场景卡文生图 Prompt 一次成型）
- [ ] 2. 角色抽帧：extract_char_frames.py 按角色卡出现镜头抽候选帧（每角色 3 张）→ 用户挑 1 张定稿 → frames/selected.json
- [ ] 3. 参考图生成：角色卡走抽帧 I2I、场景卡走文生图（每卡抽 3 张候选，用户挑 1 定稿）
- [ ] 4. ★暂停确认：用户检查角色卡/场景卡/参考图，确认后才进第二步
- [ ] 5. 第二步分析（两阶段，无字幕）：omni 听音出初稿 → qwen3.8-max 看片精修 → 详细分镜.md（生成段规划+分幕镜头细节块：布景/光影/逐秒时间轴+切镜标注；只写事实，不写提示词，不写字幕）
- [ ] 6. 第三步提示词撰写（qwen3.8-max 纯文本，无字幕）：把详细分镜细节块无损翻译 → 生视频提示词.md（段级★Prompt+参考图清单+首帧合成指引；★Prompt 首行声明无字幕）
- [ ] 7. 默认交付素材包；仅当用户明确要求时，调 wan3.0-video（默认，`--model` 可换）按生成段生成视频
```

两个硬检查点：**第 4 步必须停下来等用户确认**（第一步的卡名会被后续严格引用，错误会传导）；**第 7 步默认不执行**（生视频慢且耗费额度，约 10 分钟/段，须用户明确要求）。

## 0. 前置准备

- 环境变量 `DASHSCOPE_API_KEY` 必须已设置。
- 依赖：`pip install openai dashscope pillow -i https://mirrors.aliyun.com/pypi/simple/`（国内走阿里云镜像避免超时；PIL 用于抽帧尺寸校验与参考图放大）。
- 本地视频经 base64 编码后须 < 10MB（即原文件约 < 7MB）。超限先压缩：
  ```bash
  ffmpeg -i input.mp4 -vf "scale=-2:480" -b:v 800k -c:a aac -b:a 64k input_compressed.mp4
  ```
  注意：**抽帧要用清晰度足够的原片**（压缩版仅用于喂模型分析；抽帧 I2I 的参考帧越清晰，人脸还原越好）。
- **所有产物必须写入用户可见的工作文件夹**（用户选定的文件夹；未选定时用默认 outputs 目录），严禁只落在智能体临时 scratchpad 里。固定结构与命名：`{output}/分镜大纲.md`、`{output}/详细分镜.md`、`{output}/生视频提示词.md`、`{output}/refs/`（参考图）、`{output}/refs/frames/`（抽帧候选+selected.json）、`{output}/shots/`（视频段）——文件名固定用标准名，不要自行加日期/版本后缀（脚本遇同名会自动加 `_1` 后缀防覆盖，重跑后注意告知用户最新文件名并以其为准）。

## 1. 第一步：选角与置景（qwen3.8-max 看片直出）

```bash
python3 scripts/analyze_video.py step1 --video <本地路径或http链接> --output <输出目录>/分镜大纲.md
```

step1 默认模型 **qwen3.8-max**（可用 `--model` 覆盖），直接接收视频输入，一次产出三部分：分镜大纲（逐镜头：剧情/景别/出场人物/背景）、角色卡（每个角色一段文生图 Prompt + 标签 + 出现镜头）、场景卡（每个场景一段无人物纯环境文生图 Prompt）。System Prompt 在 [prompts/step1_system.md](prompts/step1_system.md)，其核心规则（改动前先读原文）：风格锚定"文化题材+画风+人种"三要素、忠于原片禁止美化、看不清不编造、纯色背景便于复用。

完成后**立即用文件卡片把 分镜大纲.md 交付给用户**（检查点要基于它逐字确认，只发路径或口头概述不算交付），并简述识别出的角色数/场景数/镜头数。

**角色卡的"出现镜头"字段是抽帧依据**，确认大纲时顺带核对每个角色卡的"出现镜头"是否齐全准确。

## 2. 角色抽帧（每角色 3 张候选帧，用户挑定稿）

按每个角色卡的"出现镜头"，从分镜大纲里查到对应镜头的时间区间，在每个区间内抽帧（单区间取 30%/50%/70% 三个时点，多区间取前两个区间的中点+35%/65%），ffmpeg 截成静帧：

```bash
python3 scripts/extract_char_frames.py --cards <输出目录>/分镜大纲.md --video <原片路径> --output <输出目录>/refs/frames
```

产出 `帧_<角色名>_1..3.jpg` 与 `frames.json`（角色卡名 → 帧路径列表）。**必须用 present_files 把每个角色的候选帧推送给用户**（推荐横向拼对比图），让用户为每个角色挑 1 张定稿——挑选标准：人脸清晰完整（优先近景/正面，避免远景、背影、遮挡、表情夸张帧）、无字幕压住脸、单人或该角色占主体。

用户定稿后，把结果写入 `refs/frames/selected.json`（key 必须与 frames.json 一致；值默认单帧路径，服装细节难还原时可写 ≤3 个帧路径的列表做多帧参考）：

```json
{
  "角色卡-妻子": "refs/frames/帧_妻子_2.jpg",
  "角色卡-丈夫": "refs/frames/帧_丈夫_1.jpg"
}
```

挑帧不满意可加 `--only "角色名"` 重抽单个角色；个别帧需要换时点时，直接手动 ffmpeg 截帧补进目录再写 selected.json 即可。

## 3. 参考图生成（角色卡抽帧 I2I，场景卡文生图）

用 AskUserQuestion 确认用户同意后执行（抽帧完成通常意味着已默认同意出图，可直接推进）：

```bash
# 全量：角色卡自动按 selected.json 各自帧走 I2I，场景卡走文生图，每卡 3 张候选
python3 scripts/generate_ref_images.py --cards <输出目录>/分镜大纲.md --output <输出目录>/refs \
  --frames-index <输出目录>/refs/frames/selected.json

# 只重出某张卡（用户对个别卡不满意、或换了定稿帧/改了卡 Prompt 后）
python3 scripts/generate_ref_images.py --cards <输出目录>/分镜大纲.md --output <输出目录>/refs \
  --frames-index <输出目录>/refs/frames/selected.json --only "妻子"
```

I2I 机制（脚本已内置，无需手动处理）：角色卡 Prompt 前自动拼接身份锁定指令——"参考图是该角色在原片中的真实截图帧：面部特征、发型、服装必须与参考图中的人物严格一致，不得美化或替换长相；当文字与参考帧在服装细节（款式/纹理/颜色/开合/纽扣等）上不一致时一律以参考帧为准，文字只规定构图、姿态、背景与表情"；同时 `prompt_extend=False` 防止模型改写提示词。**帧锁身份与服装细节，卡 Prompt 锁构图/姿态/背景/表情**。**多帧参考**：selected.json 的值可以是 ≤3 个帧路径的列表，脚本会把它们全部作为参考图传入（给模型更多服装证据，服装细节难还原时优先用这招）。场景卡不走 I2I，仍按卡 Prompt 文生图。

兜底与变体：
- `--ref-image <图片>`：所有角色卡统一改用这一张参考图 I2I（覆盖 selected.json），用于"把原片角色整体换成某个 IP/指定人物"的场景。
- 某角色在 selected.json 中无条目（如用户放弃抽帧）时，该角色卡自动回退纯文生图。

生成后**必须用文件展示工具（present_files）把图片真正推送给用户**——只发文件路径、只写文字描述、或仅自己 Read 查看都不算展示。推荐做法：先用 ffmpeg 把每张卡的 3 张候选横向拼成一张对比图、并附上该角色的定稿抽帧一起展示，方便用户比对挑选（重点核对：长相是否与定稿帧一致、构图是否符合卡 Prompt）：

```bash
ffmpeg -y -loglevel error -i 卡_1.png -i 卡_2.png -i 卡_3.png \
  -filter_complex "[0]scale=-2:480[a];[1]scale=-2:480[b];[2]scale=-2:480[c];[a][b][c]hstack=3" 对比_卡名_候选123.jpg
```

然后**让用户为每张卡挑选一张定稿**；将选中图路径移到 `refs/index.json` 该卡数组的第一位（后续步骤取第一张为准），落选图保留不删。产出 `refs/index.json` 记录卡名→图片路径映射，第三步参考图清单与生视频都按它取图。

## 4. ★暂停确认检查点

明确告诉用户："请确认角色卡、场景卡和参考图是否符合原片（角色参考图重点核对与抽帧定稿的长相一致性），确认后我再进行第二步。" 用户若要改卡：直接编辑**分镜大纲**中对应卡的 Prompt 文本，再用 `--only` 重出该卡参考图；若要换定稿帧：改 selected.json 后重出。**卡名一旦确认不要再改**——后续步骤严格沿用卡名做引用。

## 5. 第二步：运镜与调度（两阶段：omni 听音初稿 → max 看片精修，只写事实不写提示词，不写字幕）

复杂场景下 omni 单独产出的详细分镜质量不稳（部位幻觉、卡名笔误、格式跑偏），因此第二步拆成两阶段——omni 当"耳朵"（唯一有音频理解能力，负责台词/语气/声效/BGM），qwen3.8-max 当"终审导演"（指令遵循与结构化写作强，看片校对视觉细节与格式）。**第二步只负责"把事实写对写全"**，产出镜头细节块，不写生视频提示词（那是第三步的专职）：

```bash
# 阶段A：omni 听音+看片出初稿
python3 scripts/analyze_video.py step2 --video <同一个视频> --step1-file <输出目录>/分镜大纲.md --output <输出目录>/详细分镜初稿.md

# 阶段B：qwen3.8-max 看片精修出终稿（--draft-file 传阶段A初稿）
python3 scripts/analyze_video.py refine --video <同一个视频> --step1-file <输出目录>/分镜大纲.md --draft-file <输出目录>/详细分镜初稿.md --output <输出目录>/详细分镜.md
```

**音频事实保护**（refine 提示词已内置硬规则）：max 听不到音频，初稿中的台词原文/语气/声效/BGM 是唯一事实来源，refine 只许调整挂点位置，严禁增删改写。**说话人归属同样属音频判断，默认保留 omni 初稿归属**——refine 不得凭"画面里谁更像在说话"的主观印象改判；仅在两种硬情况下才改：①**指称对象矛盾**（台词指称的对象恰是初稿说话人自己，则必非他所言，改判为指向他的另一角色/画外音）；②omni 标注了"说话人待定"需定稿。

**无字幕硬规则**（创量版内置于 step2/refine 两版 system prompt）：即使原片带字幕压屏，时间轴一律不记录字幕内容；台词原文只进"台词"字段供配音，不为它生成任何画面文字。refine 会主动剔除初稿混入的字幕字段。

step2 默认模型 **qwen3.5-omni-plus**。产出采用**生成段（Segment）方案**——逐镜头单独生成会丢失镜头间连贯性（角色位置/动势/运镜衔接断裂），因此把连续镜头打包成生成段（**每段总时长≤30秒=创量视频模型单次直出上限**，禁止一镜一段；剧情连贯的镜头尽量打包满接近 30s，段越少跨段衔接点越少）。产出结构：开头【生成段规划表】（每段包含哪些镜头/段总时长/出场卡）；按幕分组，每幕开头【本幕角色形象汇总】；每镜头含【布景与站位】【光影】【逐秒时间轴】（动作+台词+声效+光影同步，不含字幕），相邻镜头间有【切镜】标注。**到此为止，不输出 ★Prompt 与首帧合成指引**。System Prompt 在 [prompts/step2_system.md](prompts/step2_system.md)、[prompts/step2_refine_system.md](prompts/step2_refine_system.md)。

**为什么细节块要写全布景**：静态布景信息（场景道具、陈设位置与状态、前中后景分层）是第三步提示词的主要依据，也是最容易在后续被漏掉的，第二步必须完整写全。多人同框禁止"亲密站立/依偎/相拥"等笼统词，逐人写明位置/朝向/肢体接触点/视线+微动作。

## 6. 第三步：提示词撰写（qwen3.8-max 纯文本，无损翻译官，无字幕）

第二步把事实写对后，第三步专职"把事实无损翻译成生视频提示词"。**为什么要单独一步**：★Prompt 是把多镜头细节块压缩成单段提示词的活，若在第二步多任务 pass 里顺带写，注意力分散最容易丢静态布景信息；拆成单一职责的独立 pass + 强制自检，才能把"疏忽"变成"流程上不可能疏忽"。

```bash
python3 scripts/analyze_video.py step3 \
  --step2-file <输出目录>/详细分镜.md \
  --step1-file <输出目录>/分镜大纲.md \
  --refs-index <输出目录>/refs/index.json \
  --output <输出目录>/生视频提示词.md
```

step3 默认模型 **qwen3.8-max**，**纯文本不吃视频**（事实已在第二步对画面核对完，step3 只做忠实搬运，再看片反而引入漂移、也更贵）。传入 index.json 后，参考图清单会带真实文件路径。System Prompt 在 [prompts/step3_system.md](prompts/step3_system.md)，核心规则：
- 每生成段产出三件：**参考图清单**（段首，图N↔卡名↔文件路径，作为编号承诺）+ **★视频生成 Prompt**（正文"图N（卡名）"一律以清单为准）+ **首帧合成指引**（段尾）。
- **参考图编号**：角色卡在前（按本段首次出现顺序）、场景卡在后，依次 图1..图N；★Prompt 里角色/场景一律写"图N（卡名）"，**角色外观只写"完全按图N参考图"，不复述长相**（用户明确偏好）。
- **每个时间片五要素齐全**：布景/道具状态、动作、对话、声效/BGM、光影；台词/声效原样搬运一字不改。**不写字幕**——无字幕状态由 ★Prompt 第一行统一声明"画面全程无字幕、无任何叠加文字"，时间片内不得出现任何字幕内容或压屏文字描述。
- 时间轴从 0 连续累计到段总时长、跨镜头不清零；**★Prompt 不写【切镜】行**（模型会把下一场景提前渲染到段尾、拼接对不上），段内换镜头只在时间片头部标"硬切至镜头N"；多人同框逐人写位置/朝向/接触/视线。
- **输出前强制自检**：逐条对照细节块，布景/台词/声效漏了就补、混入的字幕描述删掉、"图N（卡名）"与参考图清单逐一核对编号一致，只交付补齐后的版本。

**默认到此交付**：分镜大纲.md + refs/（含 frames/）+ 详细分镜.md + 生视频提示词.md 就是完整素材包。

## 7. 可选：自动生成视频（仅用户明确要求时；默认 wan3.0-video，`--model` 可换）

**按生成段**调用视频模型参考生视频（R2V），默认 **wan3.0-video**（用户指定其他模型时用 `--model` 覆盖），一段=一次生成。Prompt 与参考图顺序直接取自第三步《生视频提示词.md》每段的 ★Prompt 与参考图清单（图N顺序即 `--refs` 传入顺序）：

```bash
python3 scripts/generate_video.py \
  --prompt "<该生成段的★视频生成 Prompt>" \
  --refs refs/角色卡_妻子_1.png refs/场景卡_医院走廊_1.png \
  --duration <段总时长向上取整> --resolution 1080P --ratio 9:16 --output <输出目录>/shots/seg1.mp4
```

要点：
- **Prompt 里必须用"图1""图2"引用参考图**，序号按 `--refs` 传入顺序（第三步已按此写好，照抄即可）。
- 每段传该段参考图清单列出的全部参考图（≤10 张），顺序与图N一致。
- `--duration` 取该生成段总时长向上取整，范围 [2,30]（规划表已保证段≤30s）。
- **多段拼接场景必须显式传与原片一致的 `--ratio`**（竖屏 9:16 / 横屏 16:9）：默认 adaptive 会按内容自适应，可能个别段出方形，导致 concat 分辨率不匹配失败。
- **无字幕核对**：★Prompt 已声明无字幕，出片后抽查关键帧确认画面没有模型自作主张叠加的字幕/文字；发现字幕残留时，在 Prompt 首行补强声明重出该段。
- 生成约 10 分钟/段，脚本默认轮询 15s、超时 3600s。脚本会先打印 task_id——**视频 URL 和 task_id 有效期 24h**，中断后可凭 task_id 查 `GET /api/v1/tasks/{id}` 重新下载。
- 若用户选用 wan3.0-video 的经验参数：账号并发约 2 任务，多段批量提交时错开数秒即可，超额任务服务端 PENDING 排队不会失败，可用 `GET /api/v1/tasks?model_name=wan3.0-video` 核验提交状态。
- 全部生成段完成后按段号拼接：
  ```bash
  printf "file 'seg1.mp4'\nfile 'seg2.mp4'\n" > list.txt
  ffmpeg -f concat -safe 0 -i list.txt -c copy final.mp4
  ```

## 关键约束与坑

- 模型分工：step1=qwen3.8-max（看片+写卡一体），step2=qwen3.5-omni-plus（听音+运镜逐秒分析），refine/step3=qwen3.8-max（精修/提示词撰写，其中 step3 纯文本不吃视频）。qwen3.5-omni 必须 `stream=True` + `modalities=["text"]`；qwen3.8-max 走 OpenAI 兼容协议、默认开 thinking，脚本已用 `extra_body={"enable_thinking": False}` 显式关闭（analyze_video.py 按模型名自动分流）。
- **抽帧 I2I 的帧质量决定角色还原度**：定稿帧优先近景/正面/人脸完整；远景、背影、遮挡、强运动模糊、字幕压脸的帧不要选。帧单边 <240px 脚本会自动放大（模型硬要求 ≥240px），但清晰度仍以原片高清版为准。参考图产出后必须与定稿帧并排比对长相，不一致就换帧重出。
- **I2I 服装还原的三层保险**：①身份锁定前缀已内置"服装细节冲突时以参考帧为准"的仲裁；②卡 Prompt 仍要显式写明真实服装状态（"敞开不系扣""袖子挽起"等），降低仲裁难度；③服装纹理/纽扣等细节仍漂移时，把该角色在 selected.json 的值改为 ≤3 帧路径列表（多帧同时作参考，给模型更多服装证据），再 `--only` 重出。不要靠换候选图碰运气。
- **I2I 只锁角色卡**：场景卡始终走文生图；若误给场景卡传帧，脚本会自动忽略。
- 生图模型双家族支持（默认 **qwen-image-3.0-pro**）：qwen-image 系走 `MultiModalConversation.call`，size 用 宽*高（脚本自动把 2K 映射为 2048*2048），I2I 支持 1-3 张参考图 + 恰好 1 个 text；wan 系（wan2.7-image-pro）走 `ImageGeneration.call` 且**不接参考图**（--frames-index 会被警告忽略，抽帧 I2I 场景不要切 wan 系）。千问文生图最新为 **qwen-image-3.0-pro**（文档 ID 3047054，模型列表页可能未收录；n=1~6）；qwen-image-max/plus 固定单张，脚本靠补抽凑满候选数。
- 卡片 Prompt 里慎用姿态词：如"展翅"会被文生图模型直译成真翅膀；否定式描述压不住正面指令，关键形态必须用正面词显式锁定。
- 本地视频 base64 后 >10MB 会 400，先压缩（见第 0 步）；但抽帧用原片高清版。
- wan3.0-video（生视频默认模型，`--model` 可换）：必须带 `X-DashScope-Async: enable` 请求头；`reference_image` 与 `first_frame/last_frame` 互斥不能混用；图片支持 base64（data URI），本地图优先走 base64 比外链 URL 稳定；图片单边 ≥240px。
- **所有脚本都不覆盖已有文件**（自动加 `_1/_2` 后缀）。重跑不同模型/参数前无需手动备份，但拼接、汇总时注意取对最新文件。
- **平台水印处理**：抖音等平台水印在各步 system prompt 中已内置"一律忽略"硬规则——分析时当它不存在（勿当字幕/布景），复刻成片天然无水印；若产物中仍出现水印描述，按源头治理修 prompt 后重跑。
- **无字幕是硬规则**：任何步骤产物里出现字幕描述（时间轴字幕字段、★Prompt 字幕内容）都属缺陷，先改对应 system prompt 再重跑，不要手动逐处修补产物。
- 角色名/场景名必须与第一步卡名完全一致，发现模型自行改名/新增角色时，要求重跑或手动修正。

## 产出核对（最后一步必做）

1. `分镜大纲.md` 含【视频概况】+ 三部分齐全；每个镜头的"出场人物/背景"都能在角色卡/场景卡中找到同名卡；每个角色卡的"出现镜头"齐全。
2. `refs/frames/` 每个主要角色有候选帧与 selected.json 定稿；`refs/index.json` 卡数与分镜大纲卡数一致。
3. **角色参考图与定稿帧长相一致**（抽帧 I2I 的核心验收项）：逐角色并排比对，面部/发型/服装无明显偏离。
4. `详细分镜.md` 开头有【生成段规划表】且每段总时长≤30s、无一镜一段、剧情连贯的连续镜头没有过碎分段；镜头编号、时间区间与分镜大纲一致（refine 按实测看片修正区间时，同步回改分镜大纲保持两文件一致）；相邻镜头间有【切镜】标注；每镜头【布景与站位】【光影】【逐秒时间轴】齐全、布景/道具/站位写全；**每镜头时间片之和等于其声明时长**（refine 超装时压缩时间片、台词不删）；**全文无字幕字段**；逐条排查角色卡中不存在的身体部位/特征及角色名笔误。**此文件不应含 ★Prompt 或首帧合成指引**。
5. `生视频提示词.md` 每生成段有 参考图清单（段首）+★Prompt+首帧合成指引；★Prompt 第一行含"画面全程无字幕、无任何叠加文字"声明、时间轴从 0 连续累计、**不含【切镜】行/本段之外的场景内容/任何字幕描述**、每时间片五要素齐全、布景信息无遗漏、无"亲密站立"类笼统词、角色外观只写"按图N参考图"；参考图清单图N↔卡名↔路径与 index.json 一致、与正文"图N（卡名）"编号逐一相符（重点排查正文整体偏移一位的高频错误，发现以清单为准改正文）。
6. 若生成了视频：每段时长≈生成段总时长，无缺段；拼接后总时长≈原片；抽查关键帧确认**画面无字幕/无水印残留**。
7. 用 file:// 链接把最终产物交付给用户。
