# 创量需求文档编写

承接当前会话已经完成的原型设计，将最终确认的产品需求整理并写入用户提供的飞书文档。不要重新设计原型，也不要要求用户重复已经在当前会话确认的信息。

## 前置能力

- 操作飞书文档前，完整阅读并使用 `lark-doc` 与 `lark-shared` Skill。
- 需要业务流程图时，完整阅读并使用 `lark-whiteboard` Skill；使用飞书画板原生节点，不使用 SVG。
- 使用飞书文档 v2 能力读取和编辑目标文档。

## 信息优先级

按以下顺序确定需求事实：

1. 当前会话中用户最新确认的要求。
2. 当前会话中已经呈现并由用户确认的原型最终状态，包括浏览器评论、截图证据和交互决策。
3. 当前会话中较早的设计要求。
4. 用户提供的 PDF、Prompt、接口数据和其他资料。
5. 目标飞书文档中已经存在的内容。

同一事项出现冲突时采用最新指令。过滤已被后续要求覆盖的方案，不把讨论和迭代过程写进需求文档。除非用户明确要求，否则不要重新打开、操作或检查原型页面。

## 参考文件路由

- 开始写作前读取 [style-source.md](references/style-source.md) 与 [prd-style.md](references/prd-style.md)。
- 目标文档只有标题或需要调整大纲时读取 [outline-rules.md](references/outline-rules.md)。
- 编写页面设计时读取 [screenshot-placeholder.md](references/screenshot-placeholder.md)。
- 读取、写入和校验飞书文档时读取 [lark-editing.md](references/lark-editing.md)。

## 工作流程

### 1. 汇总当前会话

从当前会话提取最终有效的：

- 需求背景与目标；
- 用户操作、系统行为和业务结果；
- 业务流程、页面、弹窗和组件；
- 新增或变化的交互；
- 状态、字段、枚举、数量和校验；
- 数据保存、流转和资产沉淀规则；
- AI、模型或 Prompt 设计；
- 核心验收规则。

只保留与本次需求有关且已确认的内容。信息不足会实质改变方案时再向用户确认。

### 2. 读取风格范本

读取 `style-source.md` 指定的范本文档最新版本，提取标题层级、编号方式、语言风格、详略程度及飞书组件用法。只复用风格，不复制范本文档的剧情复刻、AI 演员或角色卡等具体业务结构。

范本文档无法访问时，以 `prd-style.md` 为兜底。范本文档或 `lark-doc` 通用样式与 `prd-style.md` 冲突时，以本 Skill 的 PRD 专属风格规则为准。

### 3. 读取目标文档

读取用户提供的飞书文档最新版本。目标文档通常只有标题；若已有正文，保留已有标题、图片、附件、画板、表格、网格和待办复选框。

### 4. 设计大纲

根据当前需求动态选择章节，不强制所有文档包含相同大纲。是否需要业务流程、页面设计、数据规则、Prompt 或验收标准，由当前功能决定。

目标文档只有标题，且用户只笼统要求“开始写需求文档”时，先在对话中给出建议大纲并等待确认。用户明确要求直接编写，或明确指定当前章节时，该指令本身即构成对应范围的写入授权，直接进入该章节。

### 5. 分阶段编写

只编写用户当前要求的部分：

- “先写背景”只写背景；
- “开始写业务流程”创建画板和步骤说明；
- “开始写页面交互”编写页面设计、截图占位和交互说明；
- “开始写 Prompt”根据实际模型任务决定内容结构；
- “开始写验收标准”先按实现方案中的能力模块创建子标题，再在各模块下使用飞书待办复选框。

不要提前生成用户尚未要求的后续章节。

### 6. 处理页面截图

不要自动控制原型、截图或上传图片。在图片位置插入以“截图内容描述：”开头的文本占位，并写清页面入口、前置状态、触发操作、关键组件和建议截图范围。

用户根据描述手动截图并替换占位文本。保留下方截图名称和交互说明。

### 7. 写入飞书

按以下规则判断是否需要写入前确认：

- 用户只提供文档并笼统要求开始编写，且目标文档只有标题时，先展示建议大纲并等待确认；
- 用户明确要求编写某个章节时，该指令即为写入授权，直接进行块级编辑，不重复确认；
- 用户明确要求“先在对话中输出”或“确认后再修改”时，先展示拟写内容并等待确认；
- 修改已有正文但替换或删除范围不明确时，先列出拟新增、替换或删除的内容并等待确认；
- 用户明确说“直接写”“直接修改”时，在其授权范围内跳过预览。

禁止整篇覆盖已有文档，禁止删除范围外内容。

### 8. 写入后校验

重新读取修改后的章节完成结构和内容校验，再按 `lark-editing.md` 在飞书可见页面检查本次写入范围的实际排版。一次处理范围内发现的全部短尾行。

- 文档开头的需求摘要是否使用飞书引用块；
- 标题层级、编号和分割线是否符合范本；
- 是否遗漏最新需求或保留过期方案；
- 页面、控件、字段和业务对象名称是否统一；
- 枚举、积分、数量、文件限制和状态是否准确；
- 段落、列表项和待办项的尾行是否仅剩 4 个以内字符或一个短词；有则改写整句并留出余量；
- 截图内容描述是否使用黄色文字并足以让用户独立复现，截图名称是否居中并使用灰色文字；
- Prompt 是否只包含当前模型任务需要的内容；
- 验收标准是否按能力模块设置子标题，模块顺序是否与实现方案一致，每项是否可以独立判断通过或失败。

## 硬性规则

- 使用简洁、确定、客观的产品语言。
- 优先描述用户操作、系统行为和业务结果。
- 只解释新增、变化或容易产生歧义的交互。
- 不解释关闭、普通输入、滚动等基础交互。
- 控件名称使用中文引号，字段和枚举使用准确值。
- 不固定需求文档大纲，不固定 Prompt 内部结构。
- 不自动截图，不自动上传截图，不虚构已经插入图片。
- 除非用户明确要求，不重新打开、操作或检查原型页面。
- 不记录原型迭代过程，只记录最终确认方案。
- 不覆盖整篇文档，不修改用户未授权的章节。
