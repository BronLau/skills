# 动态大纲规则

## 基本原则

- 根据当前会话中的最终需求生成大纲。
- 目标文档只有标题，且用户未指定章节或既有大纲时，先在对话中给出建议大纲。
- 用户已经提供大纲时优先遵循用户大纲。
- 不为了形式完整而增加无业务内容的章节。
- 围绕本次变化组织最小且充分的大纲，为每组规则选择一个主要定义位置；简短规则并入相关模块，其他章节引用而不重复展开。
- 实现方案先安排核心流程图，再按需展开页面与规则；简单需求可省略流程图，判断标准见 `prd-style.md`。

## 常见组合

普通功能可以采用：

1. 背景
2. 实现方案
   - 业务流程
   - 页面设计
3. 验收标准

涉及模型调用时可以采用：

1. 背景
2. 实现方案
3. Prompt
4. 验收标准

简单组件或局部交互调整可以采用：

1. 需求说明
2. 页面设计
3. 验收标准

以上只是选择示例。章节应各自提供必要信息；数据规则、权限、异常处理仅在承担尚未表达的关键逻辑时单列。Prompt 的程序侧接入约定归入对应实现模块，简短规则不另建章节。

## 确认规则

- 用户说“开始写需求文档”且目标文档只有标题时，先输出建议大纲。
- 用户说“先写背景”等明确章节指令时，该指令即为对应章节的写入授权，直接编写，不重复确认，也不要求先完成整份大纲。
- 用户说“先在对话中输出”或“确认后再修改”时，先展示拟写内容并等待确认。
- 用户说“直接写”或“直接修改”时，在明确范围内跳过大纲和内容预览。
- 修改已有正文但替换或删除范围不明确时，先列出变更范围并等待确认。
