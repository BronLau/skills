# 飞书文档编辑规则

## 前置

- 阅读当前 `lark-doc` 及本次操作对应的参考；认证、身份或权限问题按其路由使用 `lark-shared`。
- 命令与参数遵循当前 `lark-doc` 和 CLI 帮助，文档操作显式使用 `--as user`。
- 编辑前使用完整详细度读取目标文档，保留 block ID 和样式信息。

## 读取

- 目标文档只有标题时读取整篇。
- 已有较多内容时先读取目录，再按章节局部读取。
- 同时读取风格范本文档最新版本；无法读取时使用本 Skill 的 `prd-style.md`。

## 写入

- 精准编辑优先使用 XML 和 block 级更新。
- 优先更新已有规则的定义位置；根据最终结构插入或移动块，不将每条会话批注作为新增内容。
- 替换、合并和删除仅限用户授权范围；按 `prd-style.md` 清理重复定义和过期说明。
- 保留仍需引用的图片、附件、画板及富文本组件；编辑表格、引用或待办时保持对应结构，不因精简文字丢失资源。
- 禁止为省事使用整篇 overwrite。
- 用户明确要求编写某个章节时，该指令即为写入授权，直接进行块级编辑，不重复确认。
- 仅在用户要求先预览、目标文档只有标题且大纲尚未确认，或已有正文的替换与删除范围不明确时，先在对话中展示拟写内容并等待确认。
- 用户明确要求直接写或直接修改时，在其授权范围内跳过预览。

## 飞书组件

- 流程图的优先级与省略条件按 `prd-style.md`；使用飞书画板原生节点绘制，不使用 SVG。表格和文字补充必要细节，不重复展开图中已有的步骤。
- 页面设计默认插入原型截图，无法完成时按 `screenshot-placeholder.md` 使用黄色文字占位。
- 确需对照的字段枚举或参数使用表格。
- 并列文件或 Prompt 模块可按实际需要使用网格与文件卡片。
- 验收标准按能力模块使用三级标题分组，各组使用文档待办复选框，不使用飞书任务。

## 画板背景与配色

- 先完成节点布局与连线路由，再按所有节点、连线的完整路径（含外绕和折返）、箭头及标签的整体外接范围确定背景尺寸，并留出边距。背景置于最底层，线条绘于其上；不只按节点容器宽高铺底，也不裁切外绕线。
- 首次写入前按 `prd-style.md` 配好文字与背景，并检查转换后的原生节点。除节点的 `text` 外，还要检查 `connector.captions.data` 中的连线标签；只设置普通节点的文字颜色不会覆盖连线标签。
- 固定文字颜色需同时设置色值与自定义颜色类型。例如深色文字使用 `text_color: "#1F2329"`、`text_color_type: 1`；仅有深色色值、仍为主题颜色类型 `0` 时，不视为已固定。背景填充及连线描边同样使用固定颜色与明确的不透明度，不依赖当前主题的默认值。
- 连线默认使用 DSL `lineWidth: 2`，转换后检查原生 `style.border_width` 为细线档 `"narrow"`；箭头使用与细线协调的开放线形，原生类型为 `"line_arrow"`。以实际显示效果确认线条不会压过节点边框和文字，不因预览缩小而统一提升线宽档位。
- 转换结果丢失配色时，在写入前补齐对应颜色属性，保留节点标识、连线绑定及几何信息。工具无法保留标签配色时，使用浅色底、深色字的独立标签节点，并移除原连线文字，避免重复或重叠。

## HTML 原型附件

- 上传本次截图对应的已确认 HTML 文件，保留实际文件名，紧接“页面设计”标题插入，位于第一个页面子标题之前。使用文件卡片 XML，例如 `<figure view-type="Card"><source path="@./prototype.html" name="prototype.html"/></figure>`。
- 同一版本的原型卡片直接复用；原型更新后同步对应附件，确认新附件成功后再移除被替换的旧卡片，保留其他附件。无法取得 HTML 原文件时说明缺失，不以本地路径文字代替上传结果。
- 回读确认附件资源、文件名、`view-type="Card"` 和章节位置，并核对附件与截图来自同一原型版本。

## 截图插入

- 优先使用当前 `lark-doc` 的本地图片 XML，例如 `<img path="@./screenshots/page.png"/>`，通过 `block_insert_after` 插入对应页面标题或占位块之后。路径必须指向本次实际获取并检查过的图片；图片按比例展示，图名独立成段。
- 新页面的图片后添加 `<p align="center"><span text-color="gray">「截图名称」</span></p>`，按需补充交互说明。已有占位先保留，图片回读确认就位后再删除该占位块；沿用已有图名和仍有效的说明。
- 若采用 `docs +media-insert --file`，该命令会把图片放到文末；获取返回的图片 block ID，再用 `block_move_after` 移到目标锚点。每次结构变化后重新读取受影响范围，使用最新 block ID。
- 检查写入结果和警告，再回读目标章节确认图片资源、位置与顺序。失败或响应不确定时先核对现状，保留原有图片和占位，按截图参考决定重试或降级；只报告实际完成的状态。

## 校验

写入后重新读取目标章节完成结构和内容校验。XML 回读不包含真实页面换行，因此还需在飞书可见页面以常规文档宽度检查本次写入范围，扫描全部段落、列表项和待办项，并一次处理发现的全部短尾行。无法查看可见页面时，按 `prd-style.md` 压缩文案，并明确说明尚未完成可视版式校验。

检查：

- block 是否位于正确章节；
- 标题层级和编号是否连续；
- 是否保留原有媒体和富文本组件；
- 是否出现重复、遗漏或错误替换；
- 文案是否符合本 Skill 的内容取舍与风格规则；
- 画板回读中的文字、背景及连线描边是否保留固定配色和细线档位，背景是否包住全部路径、箭头及标签并留有边距；按文档实际显示比例检查两侧绕线、箭头和标签既可辨又不抢过节点与标题。有独立预览能力时检查深浅两种模式，否则说明已验证的范围，不以本地 PNG 正常代替飞书显示校验；
- HTML 原型附件是否为当前版本，是否以卡片视图位于“页面设计”标题下、首个页面子标题前；
- 图片是否实际就位，图名样式是否正确；未完成的截图是否保留黄色占位并说明原因，待办项是否使用正确组件。

文档写入权限不足、版本冲突或无法确认修改结果时，停止后续文档写入，保留已成功内容并说明问题。仅截图获取或图片上传失败、且正文仍可安全编辑时，按截图参考降级处理。
