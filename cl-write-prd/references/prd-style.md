# 产品需求文档风格

## 文档开头

- 在文档标题下、首个一级章节前，用一段需求摘要概括本次建设的核心变化和业务结果。
- 需求摘要固定使用飞书引用块；使用 XML 编辑时写为 `<blockquote>...</blockquote>`。

## 标题与层级

- 一级章节使用中文序号，如“一、背景”“二、实现方案”。
- 实现方案中的内容分组使用三级标题，如“业务流程”“页面设计”。
- 页面设计项使用带阿拉伯数字的四级标题，如“1. 资产页”。
- 独立章节和独立页面设计项之间使用分割线。
- 是否出现 Prompt、数据规则或验收标准等章节，由当前需求决定。

## 背景

- 使用一个简洁段落，通常控制在 100～200 字。
- 按“当前缺口 → 造成的问题 → 本次建设目标”组织。
- 不拆分市场分析、产品价值等无必要小节。
- 不使用营销化或宽泛表达。

## 业务流程

- 使用飞书画板原生节点表达主流程。
- 图下使用加粗的“步骤说明：”。
- 使用有序列表说明流程步骤。
- 每一步使用“加粗动作名称：具体说明”。
- 步骤聚焦用户动作、系统处理和最终结果。

## 页面设计

每个页面或关键交互依次包含：

1. 四级标题；
2. 页面截图或“截图内容描述”占位；
3. 使用中文引号标注的截图名称；
4. 无序列表形式的交互和业务规则；
5. 分割线。

说明只覆盖新增、变化或容易误解的交互。普通关闭、常规输入、滚动等基础操作不单独说明。

## 字段与规则

- 字段枚举、参数或对照关系优先使用两列表格。
- 控件名称使用中文引号。
- 积分、数量、文件类型、大小限制和状态值使用准确数字。
- 每条规则写清触发条件、系统行为和结果。

## Prompt

- 仅在功能确实涉及模型或 Prompt 时增加对应章节。
- 使用具体模型任务名称作为小标题。
- 有组装逻辑或多阶段处理时，可使用飞书画板表达。
- 模板、变量、动态模块、输出格式、约束、正反例和兜底规则按任务需要选择。
- 不强制拆分为输入参数、后端组装规则、有参考图或无参考图等固定结构。

## 验收标准

- 使用飞书待办复选框。
- 每项对应一项可以独立判断通过或失败的核心能力。
- 同一业务链路的关联条件可以合并在一项中。
- 顺序与实现方案和页面设计基本一致。
- 不为无关紧要的视觉细节创建大量验收项。

## 语言

- 使用简洁、确定、客观的产品语言。
- 优先使用“用户可……”“系统……”“点击后……”等句式。
- 避免“建议”“大概”“可能”“预计”等不确定表达。
- 同一对象全文使用统一名称。
- 只记录最终方案，不记录讨论过程。
- 段落、列表项和待办项优先删除标题、章节或前文已经明确的重复主语和背景，只保留当前规则需要判断的信息。
- 尾行仅剩 4 个以内字符或一个短词时，在不丢失触发条件、系统行为和业务结果的前提下重写整句，并比当前溢出长度多精简几个字，为不同显示宽度留出余量。
- 待办项包含多个可独立验收的能力时拆分；属于同一结果的关联条件保持合并并压缩表达。
- 通过精简措辞优化换行，不插入空格或手动换行，不缩小字号。
