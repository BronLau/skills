# 视频角色卡制作

把视频中的主要人物整理成可用于后续图像或视频生成的稳定角色参考图。角色卡继承源视频的视觉语言，不预设写实风格。先分析并与用户确认角色定义和风格，再开始生成；不要把模型对角色数量、外貌或风格的判断直接当作生成授权。

## 前置能力

- 使用 `ffprobe` 读取视频信息，使用 `ffmpeg` 抽取画面；优先运行本 Skill 的 `scripts/video_frames.py`。
- 检查本地关键帧时使用 `view_image`，不要只依赖文件名或低清缩略图。
- 开始生成角色卡前，完整阅读并使用 `imagegen` Skill。每个角色单独调用一次图像生成能力，并把对应关键帧标注为身份、服装或体态参考。

## 输出目录

用户没有指定位置时，在当前工作区创建：

```text
<视频文件名>_角色卡/
├── 候选帧/
├── 关键帧/
│   ├── 角色A/
│   └── 角色B/
└── 角色卡/
```

保持原视频不变。已有同名结果时使用 `_v2`、`_v3` 等版本名，不覆盖用户已有文件。不要为了汇报过程创建 Markdown 文档。

## 工作流程

### 1. 检查视频并抽取候选帧

读取时长、分辨率、帧率和方向。解析当前 Skill 目录后运行：

```bash
python3 <skill-dir>/scripts/video_frames.py sample \
  <video-path> \
  <output-dir>/候选帧 \
  --interval auto
```

`auto` 会按视频时长控制候选帧数量。依次查看生成的 `contact_sheet_*.jpg`；需要确认细微表情、遮挡或镜头切换时，再查看对应原始候选帧。

识别反复出镜、参与主要情节或承担对白/动作的人物。路人、背景群众、海报人物、屏幕内人物和短暂闪现者默认不计入主要角色。角色边界不清楚时，先增加局部采样，不要凭单帧下结论。

### 2. 形成候选角色与描述

为每个候选角色选择 3–6 个互补画面，优先覆盖：

- 清晰正面或近正面脸；
- 45 度脸或另一侧脸；
- 能判断发型、服装、体态和鞋子的中景或全身画面；
- 表情自然、运动模糊少、广告遮挡少的时刻。

按 [role-confirmation.md](references/role-confirmation.md) 编写逐角色描述。只描述画面能够支持的视觉事实；年龄使用范围，未出现的背面细节、鞋子或被遮挡服装标为“未完整展示”，不要伪装成视频事实。

同时按该参考文件分析视频的角色呈现风格。不要只给出“写实”“动漫”等宽泛标签；需要描述媒介或渲染方式、人物比例与造型、线条或边缘、明暗与材质、色彩、纹理及镜头/光照特征。默认继承视频中角色主体的主导风格；片头、广告插卡、字幕和界面元素不作为角色风格依据。

### 3. 获取用户确认

在对话中展示：

1. 建议的主要角色数量；
2. 每个角色的文本描述与身份识别锚点；
3. 建议继承的角色卡风格及其视觉特征；
4. 每个角色的代表关键帧或总览；
5. 视频没有提供、生成时必须合理推断的部分。

明确询问用户是否确认角色数量、每个角色的描述和角色卡风格，或需要增删角色、修改年龄、外貌、服装、气质与风格。把用户对这三项的明确确认视为开始生成的授权；确认前停留在分析和修订阶段，不调用图像生成。

如果用户在首次请求中已经给出角色数量、描述或风格，也要用视频证据整理成最终版本并请其同步确认，避免不同角色混用参考图或生成风格偏离目标。

### 4. 整理逐角色关键帧

用户确认后，根据时间点抽取无损 PNG：

```bash
python3 <skill-dir>/scripts/video_frames.py extract \
  <video-path> \
  <output-dir>/关键帧/角色A \
  --timestamps 24 31.5 36.5
```

逐张使用 `view_image` 检查。必要时用 `ffmpeg` 生成脸部或半身裁切，但保留原始关键帧；裁切不要切断下巴、头顶或关键发型，不使用带有另一角色大面积遮挡的画面作为主要身份参考。

每个角色单独维护参考图集合。不得把其他角色的近景作为身份参考；含有其他人物的全身帧只能作为服装或体态辅助参考，并在生成提示词中明确要求忽略其他人物。

### 5. 生成角色卡

读取 [generation-and-qa.md](references/generation-and-qa.md)，根据已确认描述填充其中的提示词模板。每个角色生成一张独立的 16:9 横向角色卡：

- 使用单行左右分区结构：左侧约 45% 为正面头肩大特写，右侧约 55% 从左到右依次为全身正面、严格 90 度侧面、全身背面；
- 左侧特写完整保留头顶、头发、脸部轮廓和肩颈，人物直视镜头，表情自然放松；
- 右侧三个全身视图从头顶完整展示到鞋底，缩放比例、头顶高度和站立基线一致，双臂自然下垂，间距均匀且互不遮挡；
- 四个画面保持同一身份、年龄感、发型、身材比例、服装和配饰；
- 四个画面统一继承用户确认的视频风格，包括人物比例、造型、线条或边缘、色彩、明暗、材质和纹理；
- 四个视图共用干净、明亮、无缝的纯白背景和与源风格兼容的柔和高调光影，不使用边框、分隔线或独立卡片底板；
- 不添加标题、角度标签、箭头、Logo、水印或场景道具。

使用内置 `imagegen` 时，把身份和服装参考的本地路径传入 `referenced_image_paths`。生成完成后，把最终图片从默认生成目录复制到 `<output-dir>/角色卡/`，不要只留下默认目录中的文件。

### 6. 校验与迭代

按 [generation-and-qa.md](references/generation-and-qa.md) 完成视觉与文件校验。重点检查四视图数量与顺序、左右区域比例、身份一致性、服装一致性、与源视频的风格一致性、完整头脚、结构或解剖错误及 16:9 比例。

发现问题时，只针对一个主要问题迭代，并在新版本提示词中重申身份、服装和已确认风格不变量。例如只修正“全身侧面不够 90 度”“背面服装发生变化”或“线条和上色偏离视频”，不要同时重写人物设定。保留较好的旧版本，生成新版本文件。

### 7. 交付

在对话中直接展示每个角色的最终角色卡，并提供绝对文件路径、图片尺寸和简短角色描述。说明背面、鞋子等哪些内容来自合理推断。不要生成额外的过程总结文件。

## 异常处理

- **缺少清晰正脸**：在确认阶段说明身份稳定性风险，请用户补充素材；用户接受风险后再生成。
- **缺少全身或背面**：在确认阶段列出需推断部分，请用户确认服装延展方式或接受合理推断。
- **角色外观变化**：把明显的换装、年龄阶段或造型变化列为同一角色的不同造型候选，由用户决定合并还是拆分。
- **视频存在多种角色风格**：区分角色主体风格与片头、广告、字幕等包装元素；若正文确有真人/动画切换或不同角色使用不同风格，在确认阶段分别列出，由用户决定按角色继承、按片段继承或统一为指定风格。
- **多人高度相似**：使用“角色A/角色B + 时间点 + 服装锚点”区分，增加关键帧后再请求确认。
- **视频过长**：先用自动间隔建立全局候选帧，再对角色密集片段使用更短间隔二次采样。
- **生成结果身份漂移**：提高身份参考的正面和 45 度近景权重，减少低质量或含他人的参考图，再做单点迭代。
